# Розгортання з NIC.UA

Інформація про NIC.UA взята з їхнього сайту на момент підготовки; тарифи й умови можуть змінюватися.

## 1. Що пропонує NIC.UA
- **Домени** (головний український реєстратор) і власні хмарні DNS-сервери з миттєвим оновленням записів.
- **Веб-хостинг NIC-S / NIC-M / NIC-L** (віртуальний, панель DirectAdmin або cPanel): SSH-доступ, попередньо встановлені PHP, Python, **Node.js** і Ruby різних версій, **PostgreSQL** і MySQL без обмеження кількості баз, безкоштовний SSL, щоденні резервні копії, 10 днів безкоштовного тесту. Дисковий простір: 1 / 5 / 10 ГБ, ліміт — 100 000 файлів на акаунт. Орієнтовні ціни при оплаті на рік: від ~219 / ~406 / ~567 ₴ на місяць.
- **Premium-хостинг** (керована хмара) — умови за запитом.
- Окремого VPS у їхньому меню зараз немає (сторонній огляд теж пише, що хмарні сервери вони припинили). Тому Docker-розгортання з `DEPLOY.md` на NIC.UA **не підходить**.

## 2. Два шляхи
**Шлях А (найнадійніший): домен у NIC.UA, сайт на VPS в іншого хостера.** Реєструєте домен у NIC.UA, у його DNS створюєте запис A на IP сервера, а сайт запускаєте за `DEPLOY_HOSTIQ.md` / `DEPLOY.md`. Усе перевірено й має HTTPS, фонові процеси та повний контроль.

**Шлях Б: сайт на хостингу NIC.UA (дешевше, без Docker).** Проєкт підготовлено й для цього: немає нативних модулів, є вхідний файл `app.js` для Node.js Selector/Passenger, схема бази без розширень (`db/schema_shared.sql`), ініціалізація без `psql` (`scripts/db-init.mjs`). Перевірено, що сайт проходить усі 70 тестів на базі з обмеженою роллю без розширень. **Але як саме NIC.UA запускає Node.js-застосунки (чи можна тримати довгоживучий Express-сервер, які ліміти пам’яті), на їхньому сайті не описано — це треба підтвердити.** Для цього є безкоштовні 10 днів.

## 3. Запитання до підтримки NIC.UA (support@nic.ua або чат) — перед оплатою
> Планую запустити на хостингу NIC-M інтернет-магазин на Node.js (Express) з PostgreSQL. Підкажіть, будь ласка:
> 1. Чи можна через панель (Setup Node.js App / Node.js Selector) запустити довгоживучий Node.js-застосунок, який відповідає на HTTP-запити на моєму домені? Які версії Node.js доступні (потрібна 18 або новіша, краще 20/22)?
> 2. Яка версія PostgreSQL (потрібна 13+)? Чи доступний `psql`/`pg_dump` по SSH? Які ліміти з’єднань і розміру бази?
> 3. Який ліміт пам’яті й кількості процесів для Node.js-застосунку? Чи не зупиняються застосунки після періоду бездіяльності?
> 4. Чи дозволені вихідні SMTP-з’єднання на портах 465/587 до зовнішнього поштового сервісу? Який ліміт листів?
> 5. Чи можна виконувати `npm install` по SSH (проєкт має ~1700 файлів залежностей)?

**Якщо відповіді на 1–3 «так» — продовжуйте шлях Б. Якщо хоч одна «ні» — шлях А.**

## 4. Налаштування на хостингу NIC.UA (шлях Б)
1. **Тариф NIC-M** (5 ГБ): на NIC-S з 1 ГБ швидко закінчиться місце під фото. Спочатку візьміть безкоштовні 10 днів для перевірки.
2. **Домен** привʼяжіть до хостингу (за потреби створіть).
3. **База даних**: у панелі створіть базу PostgreSQL і користувача; запишіть імʼя бази, користувача, пароль і хост.
4. **Файли**: завантажте розпакований проєкт у домашній каталог (наприклад, `~/grappshopp`), **поза `public_html`**. Каталог `node_modules` не завантажуйте.
5. **Ініціалізація бази** по SSH:
   ```
   cd ~/grappshopp
   cp .env.example .env     # заповніть DATABASE_URL, JWT_SECRET (мін. 32 символи), BASE_URL=https://ваш-домен
   ```
   Після створення Node.js-застосунку (крок 6) увійдіть у його віртуальне середовище (команду показує панель) і виконайте:
   ```
   npm ci --omit=dev
   node scripts/db-init.mjs db/schema_shared.sql db/seed_prod.sql
   node scripts/create-admin.mjs ваша@пошта.ua 'ДовгийПароль123' 'Ваше імʼя'
   ```
   (`db-init` не потребує `psql`. Якщо на хостингу є `psql`, можна й так: `psql "$DATABASE_URL" -f db/schema_shared.sql`.)
6. **Node.js-застосунок** у панелі (cPanel → *Setup Node.js App* / DirectAdmin → *Node.js Selector*): версія Node.js 20 або 22, режим Production, коренева папка застосунку — `grappshopp`, URL — ваш домен, **файл запуску — `app.js`**. Змінні середовища (замість `.env` або разом з ним):
   ```
   NODE_ENV=production
   DATABASE_URL=postgres://КОРИСТУВАЧ:ПАРОЛЬ@ХОСТ:5432/ІМЯ_БАЗИ   (за потреби додайте ?sslmode=require)
   JWT_SECRET=<довгий випадковий рядок>
   TRUST_PROXY=1
   BASE_URL=https://ваш-домен
   DB_POOL_MAX=3
   SMTP_URL=...   MAIL_FROM=...   ADMIN_EMAIL=...
   ```
   > `TRUST_PROXY=1` обов’язковий: без нього всі відвідувачі виглядатимуть як один IP, і обмеження частоти запитів блокуватиме їх разом.
7. **HTTPS**: увімкніть безкоштовний SSL для домену в панелі. Натисніть *Restart* у застосунку й відкрийте `https://ваш-домен/api/health` — має відповісти `{"ok":true}`.
8. Далі в адмінці: «Налаштування», «Сторінки», розділи, товари, банер.

## 5. Резервні копії
Хостинг робить щоденні копії, але робіть і власні (база + фото): у планувальнику завдань панелі додайте щоденний запуск
`bash /home/ВАШ_КОРИСТУВАЧ/grappshopp/deploy/backup-shared.sh` (потрібен `pg_dump`). Завантажуйте копії до себе раз на тиждень.

## 6. Оновлення
Завантажте нові файли поверх старих (збережіть `.env` і `uploads/`), у віртуальному середовищі виконайте `npm ci --omit=dev`, натисніть *Restart*. Зміни схеми бази подаються окремими файлами в `db/migrations/`: `node scripts/db-init.mjs db/migrations/ФАЙЛ.sql`.

## 7. Обмеження хостингу, які треба знати
- Розсилки йдуть із самого застосунку; якщо хостинг зупиняє неактивний процес, недіслані листи автоматично догодяться після наступного запуску, але для великих розсилок краще окремий сервіс (Brevo, Mailgun, SES).
- Ліміт 100 000 файлів: залежності займають ~1700 файлів, ще ~1 файл на кожне фото. Фото стискаються при завантаженні.
- Не заливайте на хостинг `.env` у `public_html`. Сайт віддається самим застосунком, каталог проєкту має лежати поза `public_html`.
