# GRAPPSHOPP — інтернет-магазин (Node.js + PostgreSQL)

Сайт, адмін-панель і сервер в одному проєкті. Сервер віддає сайт (`public/index.html`) і API (`/api/...`),
дані зберігаються в PostgreSQL, фото — у папці `uploads/`.

## Швидкий старт (Docker)
```
cp .env.example .env     # задайте JWT_SECRET (openssl rand -hex 32) і DB_PASSWORD
docker compose up -d --build
```
Сайт: http://localhost:3000. Адмін: `admin@shop.ua` / `admin123` — **змініть одразу**:
`docker compose exec app npm run set-password -- admin@shop.ua НовийПароль123`

**Розгортання на сервері з HTTPS, резервними копіями й оновленнями — див. `DEPLOY.md` (для HOSTiQ — ще й `DEPLOY_HOSTIQ.md`; для NIC.UA — `DEPLOY_NIC.md`; для Railway — `DEPLOY_RAILWAY.md`).**

## Ручний запуск
Потрібні Node.js 18+ і PostgreSQL 14+.
```
createdb grappshopp
cp .env.example .env     # вкажіть DATABASE_URL і JWT_SECRET
npm install
npm run db:init          # схема + початкові дані
npm start             # запускає src/server.mjs (на хостингу з Node.js Selector файл запуску — app.js)
```

## Оновлення вже створеної бази
Якщо базу створено до додавання сторінок футера: `psql -d grappshopp -f db/migrations/001_site_pages.sql`.

## Пошта (відновлення пароля, розсилки)
Вкажіть `SMTP_URL` (наприклад, `smtps://user:pass@smtp.provider.com:465`) і `MAIL_FROM`.
Без SMTP лист не піде: у режимі розробки код відновлення виводиться в повідомленні на сайті,
а розсилка позначається як невдала (деталі в таблиці `newsletter_deliveries`).
`MAIL_DRY_RUN=1` — лише виводити листи в консоль. Для великих розсилок використовуйте сервіс
(Brevo, Mailgun, Amazon SES) через SMTP.

## Що вміє
- Вхід, реєстрація, відновлення пароля кодом з листа, профіль, історія замовлень.
- Каталог: розділи, стать, хештеги, артикули (`GS-0001`, розмір — `GS-0001-42`), наявність по розмірах, пошук.
- Замовлення: ціни, залишки й знижки рахує **сервер** (з браузера береться лише склад кошика); залишок списується атомарно.
- Промокоди (відсоток чи сума, мінімум, ліміт, термін), новини з дзвіночком, банер з власними фото.
- Налаштування сайту й тексти сторінок футера (контакти, соцмережі, поріг безкоштовної доставки, «Угода», «Політика» тощо) редагуються в адмінці; HTML очищується від скриптів.
- Адмінка: товари з фото, розділи, замовлення зі статусами (скасування повертає залишок), облік (виручка, собівартість,
  прибуток, витрати, залишки), промокоди, розсилки, новини, банер, клієнти, звернення.

## Безпека
- Паролі — bcrypt; сесія — JWT у httpOnly-cookie (`secure` у production); захист від CSRF (заголовок `X-Requested-With`
  + SameSite); rate limit на вхід і форми; суворий CSP; фото перевіряються за вмістом файлу.
- Для production: `NODE_ENV=production`, довгий `JWT_SECRET`, HTTPS (Caddy/nginx перед сервером, `TRUST_PROXY=1`),
  зміна пароля адміна, регулярний `pg_dump` і резервна копія папки `uploads/`.

## Відомі межі
- Кошик зберігається в браузері; онлайн-оплата карткою не підключена (на сайті це лише спосіб оплати в замовленні).
- Лічильник непрочитаних новин зберігається в браузері.
