# Розгортання на Railway (без адміністрування сервера)

Підсумок: код з GitHub → Railway збирає й запускає сайт → вбудована PostgreSQL → HTTPS і домен кількома кліками.
Схему бази, початкові дані й першого адміна проєкт створює **сам** при першому запуску.

Умови Railway взято з їхньої документації на момент підготовки; перевіряйте актуальні ціни.
Орієнтири: тариф Hobby — 5 $/міс (у ці гроші входить 5 $ використання ресурсів), том для фото — 0,25 $/ГБ на місяць (на Hobby до 5 ГБ).

## Що потрібно
1. Акаунт на **github.com** (безкоштовний).
2. Акаунт на **railway.com** з тарифом Hobby (потрібна картка; перевірте, що вона проходить).
3. **Поштовий сервіс з HTTPS-API** — **Resend** або **Brevo**. Звичайний SMTP на Railway Hobby **заблоковано** (порти 25/465/587 працюють лише на Pro), тому розсилки й лист «Забули пароль» підуть через API.
4. Домен (за бажанням; без нього працює адреса `*.up.railway.app`).

## Крок 1. Покласти проєкт на GitHub
**Головне правило: файли проєкту (`package.json`, `Dockerfile.railway`, `railway.json`, папки `src`, `public`, `db`, `scripts`) мають лежати в КОРЕНІ репозиторію, а не у вкладеній папці `grappshopp/`.** Це найчастіша причина збою збірки на Railway.

Найнадійніше — через Git у терміналі (команда `cd` гарантує правильний корінь):
```
cd шлях/до/розпакованої/папки/grappshopp      # у цій папці видно package.json
git init -b main
git add .
git commit -m "GRAPPSHOPP"
git remote add origin https://github.com/ВАШ_ЛОГІН/grappshopp.git
git push -u origin main
```
(Спершу створіть на github.com порожній приватний репозиторій `grappshopp`: **New repository → Private**, без README.)

Без Git: на сторінці репозиторію **Add file → Upload files** і перетягніть **вміст** папки (виділіть усе всередині `grappshopp`, а не саму папку). Перевірка: відкрийте головну сторінку репозиторію — у списку файлів одразу мають бути `package.json`, `railway.json`, `src`, `public`, `db`, `scripts`. Якщо там єдина папка `grappshopp` — файли вкладені.

**Якщо файли вже вкладені, не перезавантажуючи:** Railway → сервіс → **Settings → Source → Root Directory** → вкажіть `/grappshopp`. Тоді Railway шукатиме `railway.json` і Dockerfile саме там.

## Крок 2. Створити проєкт на Railway
1. **New Project → Deploy from GitHub repo** → оберіть `grappshopp` (дозвольте Railway доступ до репозиторію).
2. Railway сам знайде `railway.json` і збере образ із `Dockerfile.railway`. Перший збір займає кілька хвилин; поки він не пройде, сайт не відкриється, помилки на цьому етапі нормальні (немає бази).

## Крок 3. База даних
У проєкті: **+ New → Database → Add PostgreSQL**. З’явиться сервіс з назвою `Postgres`.

## Крок 4. Змінні сервісу з сайтом
Відкрийте сервіс із сайтом → **Variables** → додайте (кнопка *Raw Editor* зручніша):
```
DATABASE_URL=${{Postgres.DATABASE_URL}}
JWT_SECRET=<довгий випадковий рядок, мінімум 32 символи>
INITIAL_ADMIN_EMAIL=ваша@пошта.ua
INITIAL_ADMIN_PASSWORD=<пароль, мінімум 10 символів>
ADMIN_EMAIL=ваша@пошта.ua
```
Решта значень (production, автоініціалізація бази, проксі, шлях до фото) уже вписані в `Dockerfile.railway`.
Адреса сайту для листів підставиться автоматично; коли підключите власний домен, додайте `BASE_URL=https://ваш-домен`.

## Крок 5. Том для фото (обов’язково)
Без нього завантажені фото **зникатимуть після кожного оновлення чи перезапуску**.
Сервіс із сайтом → **Volumes → Add Volume** (або ⌘K / Ctrl+K → *volume*) → **Mount path: `/data/uploads`**.
Перезапустіть сервіс (Redeploy).

## Крок 6. Адреса сайту
Сервіс → **Settings → Networking → Generate Domain**. Відкрийте отриману адресу `https://….up.railway.app`.
Перевірка: `https://ваша-адреса/api/health` має відповісти `{"ok":true}`.
Увійдіть: «Увійти» → ваші `INITIAL_ADMIN_EMAIL` і пароль → вкладка «Адмінка».
**Одразу після першого входу видаліть змінну `INITIAL_ADMIN_PASSWORD`** з Railway (адмін уже створений).

## Крок 7. Пошта (Resend або Brevo)
**Resend:** створіть акаунт → *Domains* → додайте свій домен і внесіть показані DNS-записи (SPF/DKIM) → *API Keys* → створіть ключ.
**Brevo:** створіть акаунт → підтвердіть відправника (адресу або домен) → *SMTP & API* → створіть API-ключ (не SMTP-пароль).
Додайте змінні (достатньо одного сервісу):
```
RESEND_API_KEY=...          або          BREVO_API_KEY=...
MAIL_FROM=GRAPPSHOPP <no-reply@ваш-домен>
```
Адреса в `MAIL_FROM` має бути на підтвердженому домені, інакше сервіс відхилить лист. Перевірте: на сайті «Забули пароль» → має прийти код.
Безкоштовні ліміти й умови сервісів перевірте на їхніх сайтах; розсилки йдуть по одному листу з паузою (`MAIL_DELAY_MS`).

## Крок 8. Власний домен
1. Сервіс → **Settings → Networking → + Custom Domain** → введіть домен. Railway покаже **CNAME-цільову адресу** (`xxxx.up.railway.app`) і TXT-запис для підтвердження `_railway-verify`.
2. У DNS вашого домену (NIC.UA чи інше місце, де керуєте DNS) додайте ці записи.
3. **Корінний домен (`grappshopp.ua`)** вимагає, щоб DNS підтримував CNAME-flattening чи ALIAS. Якщо ні — найпростіше використати піддомен **`www.grappshopp.ua`** (звичайний CNAME), а корінний домен перенаправити на `www` засобами реєстратора. Інший шлях — перенести DNS-сервери домену до Cloudflare. Чи підтримує ваш DNS-провайдер ALIAS, уточніть у нього.
4. Після підтвердження додайте змінну `BASE_URL=https://www.grappshopp.ua` і перезапустіть сервіс.
На пробному тарифі Railway дозволяє лише один власний домен; на Hobby перевірте ліміти.

## Крок 9. Налаштування магазину
В адмінці: **Налаштування** (контакти, соцмережі, поріг доставки), **Сторінки** (тексти футера; покажіть юристу), **Розділи**, **Товари**, **Банер**, **Промокоди**.

## Резервні копії
Railway зберігає ваші дані, але робіть і власні копії бази: встановіть PostgreSQL-клієнт на комп’ютер і виконайте (значення `DATABASE_PUBLIC_URL` візьміть з вкладки Variables сервісу Postgres):
```
pg_dump "ПОСИЛАННЯ_DATABASE_PUBLIC_URL" -Fc -f grappshopp_$(date +%F).dump
```
Робіть це щотижня й зберігайте файл поза Railway. Оригінали фото зберігайте у себе на комп’ютері, бо том є єдиною копією завантажених файлів.

## Оновлення сайту
Змініть файли в GitHub-репозиторії — Railway сам збере й запустить нову версію. Нові файли міграцій бази з `db/migrations` застосовуються автоматично при запуску.

## Якщо щось не працює
| Проблема | Що перевірити |
|---|---|
| Збір падає на кроках `COPY src`, `COPY public`, `COPY scripts` («not found») | файли лежать у вкладеній папці — див. крок 1 (перенести в корінь або Root Directory = `/grappshopp`) |
| Railway не бачить `Dockerfile.railway` | у **Settings → Build** перевірте, що збирач Dockerfile, а шлях `Dockerfile.railway`; запасний варіант — змінна `RAILWAY_DOCKERFILE_PATH=Dockerfile.railway` |
| Збір не проходить / «healthcheck failed» | вкладка **Deployments → логи**; чи додано `DATABASE_URL=${{Postgres.DATABASE_URL}}` і `JWT_SECRET` (мінімум 32 символи) |
| Помилка підключення до бази | назва сервісу бази має бути `Postgres` (інакше змініть її у посиланні `${{…}}`); якщо проблема лишилась, спробуйте додати `?sslmode=require` до `DATABASE_URL` |
| Фото зникають після оновлення | не створено том або шлях не `/data/uploads` |
| Не можна увійти | відкривайте сайт по `https://`; перевірте, що адмін створено (в логах рядок `[init] створено адміністратора`) |
| Не приходять листи | логи (рядки `[mail]`); ключ API; домен/відправник підтверджені; `MAIL_FROM` на цьому домені |
| Забули пароль адміна | найпростіше — «Забули пароль» на сайті (потрібна робоча пошта). Або з комп’ютера: `npm ci`, потім `DATABASE_URL="<DATABASE_PUBLIC_URL з Postgres>" node scripts/create-admin.mjs email 'новий_пароль_від_10_символів'` (внутрішня адреса бази з комп’ютера недоступна) |
