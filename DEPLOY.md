# Розгортання GRAPPSHOPP на VPS — покроково

> Найпростіший шлях без адміністрування сервера — Railway: `DEPLOY_RAILWAY.md`.
> Домен у NIC.UA? Дивіться `DEPLOY_NIC.md` (там і про хостинг NIC.UA, і як вказати DNS на ваш сервер).
> Користуєтеся HOSTiQ? Спершу прочитайте `DEPLOY_HOSTIQ.md` (який тариф обрати й що замовити), а потім виконуйте кроки нижче.

Результат: сайт на вашому домені з автоматичним HTTPS, база даних із щоденними копіями, оновлення однією командою.
Схема: **Caddy** (HTTPS) → **сайт** (Node.js) → **PostgreSQL**, усе в Docker. Назовні відкриті лише порти 80 і 443.

## 0. Що потрібно
- **VPS** з Ubuntu 22.04 або 24.04, від 2 ГБ пам’яті й 20 ГБ диска (Hetzner, DigitalOcean, Vultr, Contabo або український VPS-хостинг; орієнтовно 4–10 $/міс — перевірте актуальні тарифи).
- **Домен** (наприклад, `grappshopp.ua`).
- **Пошта для розсилок і відновлення пароля**: SMTP-сервіс (Brevo, Mailgun, Amazon SES, Gmail Workspace тощо).
- Звичайний «спільний хостинг» без Docker/Node.js **не підійде**.

## 1. Домен
У DNS домену створіть запис **A**: `grappshopp.ua` → IP вашого сервера (за бажанням і `www`). Зміни можуть поширюватися до кількох годин.

## 2. Підготовка сервера
Підключіться: `ssh root@IP_СЕРВЕРА`. Рекомендовано входити за SSH-ключем, а не за паролем.
```
mkdir -p /opt/grappshopp && cd /opt
# з вашого комп'ютера:  scp grappshopp.zip root@IP_СЕРВЕРА:/opt/
unzip grappshopp.zip
bash /opt/grappshopp/deploy/server-setup.sh
```
Скрипт встановить Docker, увімкне брандмауер (SSH, 80, 443), fail2ban і автоматичні оновлення безпеки.

## 3. Файл .env
```
cd /opt/grappshopp
cp .env.example .env
nano .env
```
Обов’язково заповніть:
```
DOMAIN=grappshopp.ua
DB_PASSWORD=...         # openssl rand -hex 16
JWT_SECRET=...          # openssl rand -hex 32
```
Для пошти: `SMTP_URL=smtps://логін:пароль@smtp.провайдер.com:465`, `MAIL_FROM=GRAPPSHOPP <no-reply@grappshopp.ua>`, `ADMIN_EMAIL=ваша@пошта` (туди приходитимуть сповіщення про замовлення й звернення).
> `DB_PASSWORD` пишіть без спецсимволів (латиниця й цифри), інакше з’єднання з базою не збережеться. Пароль у SMTP_URL із спецсимволами потрібно кодувати (`@` → `%40`).

## 4. Запуск
```
cd /opt/grappshopp
docker compose -f docker-compose.prod.yml up -d --build
docker compose -f docker-compose.prod.yml ps
curl https://grappshopp.ua/api/health        # має відповісти {"ok":true}
```
Перший запуск триває 2–3 хвилини: збирається сайт, Caddy отримує сертифікат. Якщо сертифікат не з’являється — перевірте DNS-запис і що порти 80/443 відкриті у панелі хостингу.

## 5. Адміністратор і початкові налаштування
База створюється **чистою**: без демо-товарів і без тестового адміна.
```
docker compose -f docker-compose.prod.yml exec app node scripts/create-admin.mjs ваша@пошта.ua 'ДовгийПароль123' 'Ваше імʼя'
```
(пароль — щонайменше 10 символів). Далі зайдіть на сайт → «Увійти» → вкладка «Адмінка»:
1. **Налаштування** — телефон, email, години роботи, соцмережі, OLX, поріг безкоштовної доставки.
2. **Сторінки** — перевірте тексти «Угода», «Політика», «Доставка» (покажіть юристу).
3. **Розділи**, **Товари** (фото, розміри, наявність, собівартість), **Банер**, **Промокоди**.
4. Зробіть тестове замовлення й перевірте «Забули пароль» — так ви переконаєтеся, що пошта працює.

## 6. Пошта: щоб листи не потрапляли в спам
У DNS домену додайте записи **SPF**, **DKIM** і **DMARC**, які покаже ваш SMTP-сервіс, і надсилайте з адреси на вашому домені. Для розсилок використовуйте окремий сервіс, а не особисту поштову скриньку.

## 7. Резервні копії (обов’язково)
```
cd /opt/grappshopp && bash deploy/backup.sh         # перевірка вручну
crontab -e
```
Додайте рядок (щодня о 3:00):
```
0 3 * * * /opt/grappshopp/deploy/backup.sh >> /var/log/grappshopp-backup.log 2>&1
```
Копії (база + фото) лежать у `/opt/grappshopp/backups`, зберігаються 14 днів. **Копіюйте їх ще й за межі сервера** (інший сервер, S3/Backblaze через `rclone`, або хоча б завантажуйте раз на тиждень) — копія на тому ж сервері не врятує, якщо зламається сам сервер.

## 8. Оновлення сайту
1. Завантажте нову версію проєкту на сервер поверх старої (збережіть `.env` і `backups/`).
2. `cd /opt/grappshopp && bash deploy/update.sh` — скрипт сам зробить копію, перезбере й перезапустить сайт.

Зміни схеми бази (якщо з’являться) подаються окремими файлами в `db/migrations/` — їх запускають так:
`docker compose -f docker-compose.prod.yml exec -T db psql -U grappshopp -d grappshopp < db/migrations/ФАЙЛ.sql`

## 9. Відновлення з копії
```
cd /opt/grappshopp
bash deploy/restore.sh backups/db_2026-01-15_0300.dump backups/uploads_2026-01-15_0300.tgz
```
(Другий файл — з фото — необов’язковий.) Скрипт спитає підтвердження, бо поточні дані буде замінено.

## 10. Моніторинг
- Безкоштовний UptimeRobot/BetterStack: перевіряйте `https://ваш-домен/api/health` кожні 5 хвилин, сповіщення на пошту чи в Telegram.
- Логи: `docker compose -f docker-compose.prod.yml logs -f app` (сайт), `... logs caddy` (HTTPS).
- Місце на диску: `df -h`. Раз на місяць `docker system prune -f`.

## 11. Якщо щось не працює
| Проблема | Що перевірити |
|---|---|
| Сайт не відкривається по HTTPS | `logs caddy`; DNS-запис A; порти 80/443 у панелі хостингу |
| Не вдається увійти (одразу виходить) | сайт має відкриватися саме по `https://`; `DOMAIN` у `.env` без `https://` |
| «Помилка сервера» | `logs app`; чи запущена база (`ps`) |
| Не приходять листи | `SMTP_URL`; `logs app` (рядки `[mail]`); таблиця `newsletter_deliveries` (поле `error`) |
| Змінили `DB_PASSWORD` після першого запуску | база вже створена зі старим паролем. Якщо даних ще немає: `docker compose -f docker-compose.prod.yml down -v` і запуск заново (**видаляє всі дані**) |

## 12. Інші варіанти
- **Railway / Render / Fly.io**: підійдуть, якщо підключити керовану PostgreSQL (виконати `db/schema.sql` і `db/seed_prod.sql`), задати змінні з `.env.example` та… **постійний диск для папки `uploads`** — без нього завантажені фото зникатимуть після кожного перезапуску. Для хмарних сервісів без диска фото краще перенести в об’єктне сховище (S3/R2) — це доробка коду.
- **Спільний хостинг (cPanel)**: не підходить (потрібні Node.js 18+ і PostgreSQL).
